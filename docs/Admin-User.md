# 管理者権限 仕様書 (Admin User Specification)

## 1. 概要
本アプリケーションでは、ユーザーの権限を「管理者」と「一般ユーザー」の2段階に分け、利用可能な機能を制限します。これにより、制作者以外のユーザーが誤ってゲームデータを書き換えることを防ぎ、テストプレイに専念できる環境を提供します。

## 2. 権限の定義
- **管理者 (Admin)**: 全ての編集機能（マップ、キャラクター、イベント等）およびプレイテストを利用可能。
- **一般ユーザー (User)**: プレイテスト機能のみを利用可能。

## 3. データ構造 (Firestore)
権限の判定は、Firestoreの以下のパスにドキュメントが存在するかどうかで行います。

- **コレクションパス**: `/admin/{userId}`
- **ドキュメント内容**:
  ```json
  {
    "isAdmin": true
  }
  ```
※ `userId` は Firebase Authentication の UID と一致させる必要があります。

## 4. セキュリティルール
`firestore.rules` にて、ユーザーが自分自身の管理者情報を読み取れるように設定されています。これにより、クライアントサイドでの権限チェックを安全に行うことができます。
```rules
match /admin/{userId} {
  allow read: if isOwner(userId);
}
```

## 5. UI/UX の制限ロジック (実装予定)
共通レイアウト（`layout.tsx`）において以下の制御を実装します。
- **権限チェック**: ログインユーザーの UID に基づき、`/admin/{userId}` ドキュメントの存在を監視。
- **サイドバーの動的表示**: 
    - 管理者の場合：全てのメニューを表示。
    - 一般ユーザーの場合：「プレイテスト」および「ログイン/ログアウト」のみを表示。
- **アクセスガード**: 一般ユーザーが直接エディター画面（例: `/character-editor`）の URL を開いた場合、自動的に `/play-test` へリダイレクトする。

## 6. 管理者の追加方法
現時点では管理ユーザーを追加するためのUIは存在しません。以下の手順で Firebase Console から手動で設定します。
1. Firebase Console の Firestore データベースを開く。
2. `admin` コレクションを選択（存在しない場合は作成）。
3. [ドキュメントを追加] をクリック。
4. **ドキュメント ID**: 管理者にしたいユーザーの `UID` を入力。
5. **フィールド**:
    - 名前: `isAdmin`
    - タイプ: `boolean`
    - 値: `true`
6. 保存をクリック。
