# 広告収益化ロードマップ & 指標 (Monetization Roadmap)

## 1. 広告実装フェーズの比較と可視化

実装の難易度（ハードル）と、ユーザー体験・収益性のバランスを段階的に整理しました。

| フェーズ | 実装内容 | 技術的ハードル | 収益性 | 主な機能・メリット |
| :--- | :--- | :--- | :--- | :--- |
| **Phase 1** | **ログイン画面・埋め込み広告** | ★☆☆☆☆ (低) | 低 | 設置が容易。訪問者全員に表示。 |
| **Phase 2** | **アセット一覧・インフィード** | ★★☆☆☆ (中) | 中 | 制作作業中に自然に表示。CTRが高い傾向。 |
| **Phase 3** | **H5 Games: インタースティシャル** | ★★★☆☆ (中) | 高 | マップ遷移時などの区切りでフル画面表示。 |
| **Phase 4** | **H5 Games: リワード広告** | ★★★★★ (高) | 最高 | 広告視聴でレアアイテム・回復等の特典を付与。 |

## 2. 各ステップの詳細解説

### Phase 1: ログイン画面への埋め込み (ディスプレイ広告)
*   **実装内容**: `LandingScreen.tsx` の説明セクションの間やフッター付近に広告ユニットを配置。
*   **ハードル**: 
    *   **技術**: Google 提供の `<ins>` タグを React の `useEffect` で初期化するのみで完了。
    *   **ポリシー**: ログイン画面は文字数が少ないため、AdSense の「コンテンツ不足」による審査落ちを防ぐため、1000文字以上のサービス解説テキストを併設する必要がある。

### Phase 2: H5 Games Ads (インタースティシャル)
*   **実装内容**: プレイテスト中の「マップ遷移（境界線越え）」や「ルームへの出入り」のタイミングで広告を挿入。
*   **ハードル**: 
    *   **UX**: 頻繁すぎるとプレイを阻害するため、遷移3回につき1回表示するなどのカウンタ制御が必要。
    *   **技術**: AdSense の Game Placement API の非同期処理を `PlayTestClient` に統合。

### Phase 3: H5 Games Ads (リワード広告)
*   **実装内容**: 「動画を見て HP を全回復」「動画を見てレアな収集ポイントを解放」などのゲーム連動機能。
*   **ハードル**: 
    *   **技術**: 広告の視聴完了イベントを受け取り、成功時のみ `hp` ステートを更新したり、`inventory` にアイテムを追加するロジックの実装。
    *   **バランス**: ゲームバランス（経済圏）を壊さないような特典設計。

## 3. 追跡すべき主要指標 (KPI)

収益性を正しく評価するために、以下の数値を定期的に確認します。

| 指標 | 定義 | 目標値 (目安) | 改善策 |
| :--- | :--- | :--- | :--- |
| **CTR (クリック率)** | 広告表示に対するクリックの割合 | 0.5% - 2.0% | 広告の配置場所や関連性の見直し |
| **eCPM (インプレッション単価)** | 1000回表示あたりの推定収益 | 50円 - 300円 | H5 Games Ads 等の高単価ユニットの活用 |
| **Ad completion (視聴完了率)** | リワード広告が最後まで見られた割合 | 70%以上 | リワード（報酬）の魅力度を高める |
| **Session Duration (滞在時間)** | ユーザーが1回に滞在する平均時間 | 5分以上 | エディターの操作性向上、チュートリアルの充実 |
