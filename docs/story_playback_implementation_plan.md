# プレイテストのストーリー再生 実装計画 (v1.2)

このドキュメントは、プレイテストモードに「グランドナラティブ（物語）」の再生機能を統合するための実装手順を定義します。
一般ユーザーも利用可能な常設機能として、進行状況や解放条件に応じた物語の再生を可能にします。

## 1. 目標
プレイテスト中に、作成済みのナラティブシーケンス（`narrativeSequences.json`）を読み込み、ゲーム内メニューから再生できる仕組みを構築します。これはデバッグ用ではなく、プレイヤーが物語を追体験するための正式なゲーム機能として実装します。

## 2. 再生トリガーとアクセスの仕組み

### 2.1. ストーリー・アーカイブ (常設メニュー)
*   **内容**: ゲーム内のメニュー（サイドバーまたは専用UI）から、これまでに見た、あるいは解放されたストーリーの一覧を表示。
*   **用途**: プレイヤーが物語を振り返る、または特定のイベント後に物語を再生する。
*   **解放条件 (将来)**: `playtestSaves` 内の `flags` や進行度データをチェックし、条件を満たしたシーケンスのみを表示。

### 2.2. イベント・トリガー (自動再生)
*   **内容**: 特定のNPCへのインタラクションやマップ侵入時に、自動的に対応するシーケンスを開始。
*   **設定**: `PlacedObject` の `eventId` に `story:シーケンスID` を設定することで、会話の代わりにカットシーンを開始。

---

## 3. 実装フェーズ

### フェーズ1：ストーリーメニューの実装
*   **`play-test-client.tsx`**:
    *   ゲーム内メニューに「物語（Story）」セクションを追加。
    *   `/public/data/narrativeSequences.json` をロードし、一覧を表示。
    *   (初期実装) 全てのシーケンスを表示。(将来) `flags` に基づくフィルタリング。

### フェーズ2：カットシーン・エンジンの統合
*   **状態管理**: `gameState` に `'cutscene'` を追加し、再生中はプレイヤー操作をロック。
*   **描画ロジック**: `SequencePlayerClient` の「移動・アニメーション・ビデオ再生」ロジックを `PlayTestClient` に統合。
*   **マップ同期**: シーケンスで指定された `mapId` と現在のプレイヤー位置を一時的に退避し、カットシーン用マップへ遷移。

### フェーズ3：ダイアログとイベントの同期
*   **イベント連携**: シーケンス内のウェイポイントに到達した際、Firestoreの `eventFlows` をトリガー。
*   **UIレイヤー**: ゲーム画面上にオーバーレイでダイアログを表示。

### フェーズ4：終了後のゲーム復帰
*   1. カットシーン終了。
*   2. プレイヤーをカットシーン開始前の座標・マップへ戻す（または指定の地点へ移動）。
*   3. `gameState` を `'playing'` に戻し、操作を解放。

---

## 4. 考慮事項
*   **セーブデータの保護**: カットシーン再生中はオートセーブを停止。
*   **解放条件の管理**: `backend.json` に「シーケンス解放に必要なフラグ」の定義を追加検討。
*   **BGMの排他制御**: プレイ中のBGMとシーケンス用BGMが重ならないよう、再生開始時にフェードアウト/停止処理を実装。
