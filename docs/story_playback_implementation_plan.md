# プレイテストのストーリー再生 実装計画

このドキュメントは、プレイテストモードにストーリーエディターで作成された「ストーリーシーケンス（カットシーン）」を統合するための詳細な設計と実装手順を定義します。

## 1. 目標
プレイテスト中に、特定の条件を満たした際に「カットシーンモード」へ移行し、キャラクターの自動移動やダイアログ再生を行うことで、RPGとしてのナラティブ体験を強化します。

## 2. トリガーの仕組み（提案）

ストーリーを開始するためのトリガーとして、以下の4つの方式を提案します。

### 2.1. インタラクション・トリガー (決定済み)
*   **内容**: NPCに話しかける、または看板などのオブジェクトを調べた際に開始。
*   **設定**: `PlacedObject` の `eventId` に `story:シーケンスID` を設定。
*   **用途**: 村の長老に話しかけた際に始まる重要な会話シーンなど。

### 2.2. エリア侵入トリガー (提案)
*   **内容**: プレイヤーがマップ上の特定の範囲（座標）に入った瞬間に自動で開始。
*   **設定**: マップエディターで「不可視のトリガーオブジェクト」を配置し、その判定範囲にプレイヤーが入ったかを監視。
*   **用途**: 城の門をくぐった瞬間に衛兵に呼び止められるシーン、ボスの部屋に入った瞬間の演出など。

### 2.3. マップロード・トリガー (提案)
*   **内容**: 特定のマップ（区画）に遷移した直後に開始。
*   **設定**: `MapCell` データのプロパティに `onLoadStoryId` を追加。
*   **用途**: 初めての街に入った際に見渡すようなカメラワーク（将来的な拡張）や、導入シーン。

### 2.4. フラグ・コンビネーション・トリガー (提案)
*   **内容**: 特定のアイテムを入手した、または特定のフラグが立った際に開始。
*   **用途**: 重要なアイテムを拾った直後に背後に敵が現れるシーンなど。

---

## 3. 実装フェーズ

### フェーズ1：エディターの拡張
*   **`map-editor-client.tsx`**:
    *   インスペクターに「ストーリー選択」ドロップダウンを追加。
    *   `/public/stories/stories.json` からリストを取得し、選択されたIDに `story:` プレフィックスを付けて `eventId` に保存。

### フェーズ2：ゲーム状態の定義
*   **`play-test-client.tsx`**:
    *   `gameState` 型に `'cutscene'` を追加。
    *   `cutscene` 中は `handleKeyDown` と `handleMapClick` を無効化。

### フェーズ3：再生エンジンの統合
*   **ロジックの移植**: `sequence-player-client.tsx` から移動計算とアニメーション更新ロジックを `PlayTestClient` の `useFrame` (または `requestAnimationFrame` ループ) へ統合。
*   **動的配置**: シーケンス開始時、ストーリーファイルに定義されたキャラクターをマップ上にインスタンス化（既存のNPCとは別に一時的に生成）。

### フェーズ4：イベント・演出との連携
*   **ウェイポイント連動**: キャラクターが `eventId` を持つウェイポイントに到達した際、既存の `activeEvent` システムを呼び出し、ダイアログを表示。
*   **音声再生**: ウェイポイントまたはダイアログに紐づくボイスファイルの再生。

---

## 4. 終了と復帰のフロー
1.  ストーリー内のすべてのキャラクターが最終目的地に到達する。
2.  関連するすべてのイベント（ダイアログ）が終了する。
3.  `gameState` を `'playing'` に戻す。
4.  カットシーン用に生成した一時キャラクターを削除し、プレイヤーの操作を解放する。

## 5. 将来の拡張性
*   **カメラ制御**: カットシーン中、特定のキャラクターをカメラが追う（追尾対象の変更）機能。
*   **フェード演出**: シーンの切り替わり時に画面を黒転させるフェードイン・アウト。
