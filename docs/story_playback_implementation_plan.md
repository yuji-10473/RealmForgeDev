# プレイテストのストーリー再生 実装計画 (v1.1)

このドキュメントは、プレイテストモードに「ストーリーシーケンス（カットシーン）」を統合するための実装手順を定義します。
当初の目標として、既存のシーケンスプレイヤーと同様に `narrativeSequences.json` を読み込み、任意のタイミングで再生できる仕組みを構築します。

## 1. 目標
プレイテスト中に、作成済みのナラティブシーケンスをリストから選択して即座に実行できる機能を実装し、その後にマップ内のアクションと連動した自動再生機能を拡張します。

## 2. トリガーの仕組み

### 2.1. マニュアル・トリガー (最優先実装)
*   **内容**: プレイテスト画面のUI（デバッグメニューまたはストーリー専用ボタン）から、`narrativeSequences.json` に定義されたシーケンスを一覧表示し、クリックで開始。
*   **用途**: 開発中の演出確認、特定のカットシーンのデバッグ再生。

### 2.2. インタラクション・トリガー (フェーズ2)
*   **内容**: 特定のNPCやオブジェクトに話しかけた際に、紐付けられたシーケンスを開始。
*   **設定**: `PlacedObject` の `eventId` に `story:シーケンスID` を設定。

### 2.3. 自動実行トリガー (将来的な拡張)
*   **エリア侵入**: 不可視のトリガー範囲に入った際に自動開始。
*   **マップロード**: 特定のマップに入った直後に開始（オープニング演出など）。
*   **フラグ・条件**: 特定のアイテム入手や進行フラグが立った際に開始。

---

## 3. 実装フェーズ

### フェーズ1：プレイテストUIの拡張とデータロード
*   **`play-test-client.tsx`**:
    *   `/public/data/narrativeSequences.json` をロードするロジックを追加。
    *   画面上に「ストーリー再生」ボタンまたはドロップダウンを配置（管理者モード限定）。
    *   選択されたシーケンスIDに基づき、関連するストーリーステップを解析。

### フェーズ2：カットシーン・エンジンの統合
*   **状態管理**: `gameState` に `'cutscene'` を追加。
*   **エンジン移植**: `sequence-player-client.tsx` の移動・アニメーション計算ロジックを `PlayTestClient` のループに統合。
*   **動的生成**: シーケンスに登場するキャラクターを、既存のNPCとは別に一時的なエンティティとしてマップに生成。

### フェーズ3：イベント・ダイアログの同期
*   **ウェイポイント連動**: キャラクターが目的地に到達した際、`eventFlows` をトリガーしてダイアログを表示。
*   **UI制御**: ダイアログ表示中はキャラクターの移動を一時停止し、ユーザーの「次へ」操作を待機。

### フェーズ4：終了と復帰
*   1. シーケンスの全ステップ（ビデオ含む）が完了。
*   2. 生成された一時キャラクターを削除。
*   3. `gameState` を `'playing'` に戻し、プレイヤーの操作を解放。

---

## 4. 考慮事項
*   **カメラ追従**: カットシーン中、カメラをどのキャラクターにフォーカスするか。
*   **BGM管理**: シーケンス独自のBGM設定がある場合、元のマップBGMを一時停止・復帰させる処理。
*   **セーブデータ**: カットシーンの進行中にセーブを行った場合の挙動（基本的にはカットシーン中はセーブ不可を推奨）。
