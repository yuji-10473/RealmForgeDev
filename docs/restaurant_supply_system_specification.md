# 料理屋納品システム 仕様書 (Restaurant Supply System)

## 1. 概要
本システムは、プレイヤーが料理屋のレシピに必要な素材を「納品（補充）」し、1日経過した後にその売上報酬を受け取ることができる仕組みを定義します。単にアイテムを売却するよりも効率的にゴールド（K）を稼ぐ手段を提供します。

## 2. 納品フロー (Supply)
プレイヤーは料理屋のメニューから、特定の料理の素材を補充することができます。

### 2.1. 納品アクション
- **トリガー**: 料理屋の店主との会話、または店内の「注文票」オブジェクトとのインタラクション。
- **条件**: `dishes.json` に定義されているレシピの材料（`ingredients`）を所持していること。
- **処理**:
    1. インベントリから対象の素材アイテムを消費。
    2. 消費した素材のIDと数量を、セーブデータの `suppliedIngredients` に加算して記録。

## 3. 売上精算ロジック (Settlement)
日付が進んだ際に、前日までに納品された素材から「料理が何品作れるか」を計算し、売上として報酬を付与します。

### 3.1. 発生タイミング
- **トリガー**: [日付システム](day_system_specification.md)に基づき、布団で休息して日付（`day`）がカウントアップされた瞬間。

### 3.2. 報酬計算式
納品された素材の在庫状況と `dishes.json` のレシピを照らし合わせ、以下の通り計算します。
- **作れる品数**: 在庫素材から製造可能な最大品数を算出。
- **報酬額**: `完成した料理の数 * 料理の基本回復量 (recoveryAmount)`
- **ボーナス**: 現時点ではなし。

### 3.3. 在庫（端数）の保持
- 料理の製造に使用されなかった素材（レシピの必要数に満たない端数）は、翌日以降も `suppliedIngredients` に保持されます。
- これにより、数日に分けて素材を少しずつ納品しても、必要数が揃ったタイミングで売上が発生します。

### 3.4. 報酬の受け取り
- **自動加算**: 計算された合計金額がプレイヤーの `gold` に直接加算されます。
- **通知**: 起床時に「昨日の料理の売上：XXX K を受け取りました！」というトースト通知が表示されます。

## 4. データ構造
### 4.1. Firestore (playtestSaves/{userId})
`suppliedIngredients` には、納品された累計素材数がアイテムIDごとに記録されます。
```json
{
  "suppliedIngredients": {
    "item_meat": 7,
    "item_bread": 2
  }
}
```
※例えばレシピが「肉3、パン1」で1品の場合、上記データからは2品が製造され、肉1が端数として残ります。

## 5. UI/UX 表示
- **納品画面**: ショップシミュレーター内に「納品」タブを追加し、レシピと現在の店在庫（端数）、および所持素材の対照表を表示します。
- **達成感の演出**: 納品した素材が翌日ゴールドに変わることで、村の経済に貢献している感覚をプレイヤーに与えます。
