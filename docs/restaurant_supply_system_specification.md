# 料理屋納品システム 仕様書 (Restaurant Supply System)

## 1. 概要
本システムは、プレイヤーが料理屋のレシピに必要な素材を「納品（補充）」し、1日経過した後にその売上報酬を受け取ることができる仕組みを定義します。単にアイテムを売却するよりも効率的にゴールド（K）を稼ぐ手段を提供します。

## 2. 納品フロー (Supply)
プレイヤーは料理屋のメニューから、特定の料理の素材を補充することができます。

### 2.1. 納品アクション
- **トリガー**: 料理屋の店主との会話、または店内の「注文票」オブジェクトとのインタラクション。
- **条件**: `dishes.json` に定義されているレシピの材料（`ingredients`）を所持していること。
- **処理**:
    1. インベントリから対象の素材アイテムを消費。
    2. 消費した素材のIDと数量を、セーブデータの `suppliedIngredients` に記録。

## 3. 売上精算ロジック (Settlement)
日付が進んだ際に、前日までに納品された素材が「売れた」と見なして報酬を計算します。

### 3.1. 発生タイミング
- **トリガー**: [日付システム](day_system_specification.md)に基づき、布団で休息して日付（`day`）がカウントアップされた瞬間。

### 3.2. 報酬計算式
納品された各素材に対して、以下の計算式で報酬額を算出します。
- **基本報酬**: `素材の基本価格 (recoveryAmount) * 1.5`（卸値ボーナス）
- **ボーナス**: 特定の「おすすめ料理」の素材である場合、さらに 20% の上乗せ。
- **好感度影響**: 料理屋店主の[好感度](affection_system_specification.md)に応じて、最大 10% の追加報酬。

### 3.3. 報酬の受け取り
- **自動加算**: 計算された合計金額がプレイヤーの `gold` に直接加算されます。
- **通知**: 起床時に「昨日の料理の売上：XXX K を受け取りました！」というトースト通知が表示されます。
- **リセット**: 精算完了後、`suppliedIngredients` データは空にリセットされます。

## 4. データ構造
### 4.1. Firestore (playtestSaves/{userId})
```json
{
  "suppliedIngredients": {
    "item_meat": 10,
    "item_bread": 5
  }
}
```

## 5. UI/UX 表示
- **納品画面**: ショップシミュレーター内に「納品」タブを追加し、レシピと所持素材の対照表を表示します。
- **達成感の演出**: 納品した素材が翌日ゴールドに変わることで、村の経済に貢献している感覚をプレイヤーに与えます。
